# Доступ для клубов — отдельный сайт

Выдача доступа к HandForge Manager: клуб входит логином и паролем, видит
свой срок и скачивает программу; оператор заводит клубы, выбирает срок,
получает готовое сообщение для отправки, продлевает и закрывает доступ.

**Данные турниров сюда не попадают.** Турниры, игроки и рейтинги живут в
базах рядом с программой на компьютере клуба (`tournament_archive.db`,
`player_directory.db`) и никуда не передаются. Сайт знает только клуб,
логин, срок и отметки входов.

## Три входа

| Кто | Где | Что делает |
|---|---|---|
| Клуб | `/` | ТОЛЬКО скачивает программу, без всякого входа |
| Оператор | `/admin.html` | заводит клубы, продлевает, закрывает доступ |
| Сама программа | `POST /api/program/check`, `/api/program/refresh` | вход клуба: логин и пароль вводятся в программе при «Создать турнир» |

**Входа для клубов на сайте нет** (решение оператора 20.10.2026): «они
зашли, кнопку скачали, скачали программу, и всё, и в самой программе
вводят логин и пароль». Два места для одного логина путали бы клубы.

Поэтому «последний вход» в учёте -- это последний запуск программы
клуба (её проверка срока), а скачивания считаются общим числом: клуб при
скачивании неизвестен.

В программе без логина работает всё, кроме турниров: камеры, проверка
распознавания, микрофоны, голос, игроки, архив, рейтинги (решение
оператора 19.10.2026).

## Сроки

Тест 3 дня · 1 месяц · 3 месяца · 1 год · свой срок (число дней).
Продление действующему клубу прибавляется к остатку, просроченному --
считается от сегодня; логин при этом не меняется.

## Запуск у себя

```
npm install
npm run dev        # http://localhost:8890, база -- файл access.db рядом
```

В местном запуске пароль управления -- `test-admin` (см. `src/dev.js`),
ссылка на сборку подставная. Проверки: `npm test` (25 проверок).

## Выкладка (бесплатно)

Сайт устроен так же, как основной: Node + Express, база -- Postgres
(Render не даёт постоянного диска, файл SQLite там не переживёт
перезапуск; драйвер выбирается сам по `DATABASE_URL`, схему править
руками не надо).

Что должен сделать оператор:

1. **База.** В том же бесплатном Postgres (Neon), где живёт основной
   сайт, создать ОТДЕЛЬНУЮ базу `handforge_access` и взять строку
   подключения.
2. **Сервис.** В Render создать новый Web Service из этого репозитория,
   Root Directory = `access`, Build = `npm install`, Start = `npm start`,
   план Free.
3. **Настройки сервиса** (Environment):
   - `DATABASE_URL` -- строка подключения из п.1;
   - `ADMIN_PASSWORD` -- пароль входа в учёт клубов (придумать длинный,
     он открывает выдачу доступа);
   - `JWT_SECRET` -- длинная случайная строка (Render умеет сгенерировать);
   - `SITE_URL` -- адрес сайта, он попадает в сообщение клубу;
   - `RELEASE_URL` -- ссылка на архив сборки (см. п.4);
   - `RELEASE_VERSION`, `RELEASE_SIZE` -- что показать клубу («18.10.2026»,
     «1,4 ГБ»);
   - `OFFLINE_GRACE_DAYS` -- сколько дней программа работает без связи
     после удачной проверки (по умолчанию 3).
4. **Сборка программы.** Архив большой, на сайте ему не место: кладём в
   GitHub Releases (бесплатно, до 2 ГБ на файл) и даём ссылку в
   `RELEASE_URL`. Полная сборка с поддержкой видеокарты -- 4,61 ГБ, в
   лимит не влезает; облегчённая (без CUDA) -- около 1-1,5 ГБ.

## Чего здесь ещё нет

* Окно входа в самой программе (`POST /api/program/check` его ждёт).
* Рассылка логина клубу прямо из программы -- пока кнопка «скопировать
  сообщение».
* Проверка по компьютеру (один логин -- один зал): сейчас логином можно
  пользоваться с нескольких машин.
